# 직접 채울 내용

## 1. 가장 먼저 넣으면 좋은 자료

| 프로젝트  | 자료                                 | 전달하려는 내용                     |
| --------- | ------------------------------------ | ----------------------------------- |
| 메엠지지  | 캐릭터·랭킹·계산기 화면              | 실제 서비스의 사용 흐름             |
| 메엠지지  | 동일 조건의 랭킹 행 데이터 전후 비교 | 70.4KB → 3.5KB의 측정 범위          |
| 메엠지지  | 탭 전환 전후 Network·서버 로그       | 불필요한 외부 호출 5건 제거         |
| 메엠지지  | iOS 저장 전후 PNG                    | 이미지 누락의 실제 증상과 수정 결과 |
| 하루몽    | 두 계정의 교환일기 시연              | 홈 이외 화면에서도 이벤트 반영      |
| 하루몽    | 이미지 측정 환경·횟수                | 기존 단일 사례 수치의 재현 조건     |
| 하루몽    | 캐시 재방문·수정 동기화 영상         | 요청 재사용과 화면 일관성           |
| 컬리 클론 | 두 종류의 공통 모달 화면             | slot으로 달라지는 내용과 공통 동작  |
| 컬리 클론 | 상품 두 번 담기 영상                 | 수량 합산·배지 갱신                 |
| 컬리 클론 | 목록→상세→홈 화면                    | 최근 본 상품 누락 수정              |

스크린샷은 예시 이미지로 대체하지 않았습니다. 실제 기여를 보여주는 자료를 사용하세요. 테스트 계정의 개인정보나 토큰은 가린 뒤 넣으세요.

## 2. 대표 이미지 추가

`public/images`에 이미지를 추가한 뒤 `src/data/projects.json`에서 해당 프로젝트 필드를 채웁니다.

```json
"coverImage": "/images/maplemgg-overview.webp",
"coverCaption": "캐릭터 검색과 성장 현황을 확인하는 상세 화면"
```

빈 문자열이면 독자 화면에서는 숨겨집니다. 작성 메모를 켜면 자료를 넣을 위치가 표시됩니다.

## 3. 회고와 협업 경험 작성

각 프로젝트의 `personal`에는 다음 형식의 항목이 있습니다. `value`만 채우면 작성 메모를 끈 상태에서도 본문에 표시됩니다.

```json
{
  "label": "협업 사례",
  "hint": "실제로 조율한 이슈와 PR을 정리해 주세요.",
  "value": ""
}
```

아래 질문의 답을 본인 경험으로 작성하세요. 구현 코드에서 추정해 답을 만들어 넣지 않았습니다.

- 문제를 처음 알게 된 계기는 무엇이었나요?
- 본인이 맡은 범위와 팀원이 맡은 범위는 어디까지였나요?
- 다른 해결 방법과 비교해 무엇을 선택했나요?
- 시간·운영 환경·팀 합의 등 실제 제약은 무엇이었나요?
- 어떤 사용자 피드백이나 검증으로 완료를 판단했나요?
- 다시 구현한다면 무엇을 바꾸고 싶은가요?

## 4. 사례별 증거 이미지와 메모

각 `cases` 항목의 `image`와 `caption`에 이미지 경로와 설명을 넣습니다. 이미지 확대를 지원합니다. `missing`은 작성 메모에서 보이는 안내이며 자료 보완이 끝나면 빈 문자열로 바꾸세요.

```json
"image": "/images/tab-requests.webp",
"caption": "동일 캐릭터의 탭 전환 전후 요청 비교. 환경: 직접 기입",
"missing": ""
```

## 5. 코드 발췌

`code`에는 `file`, `code`, `line`, `url`이 있습니다. 소스를 갱신할 때는 코드 문자열뿐 아니라 원본 커밋·시작 행도 함께 바꾸세요. 일부 발췌이므로 독립 실행 가능한 전체 코드가 아닙니다.

## 6. 기존 원고에서 보류한 내용

교체 전 원고는 `docs/previous-content.txt`에 남겼습니다. 다음 내용은 근거나 맥락을 더 확인한 뒤 복원할 수 있습니다.

- 검색 유입·색인 개선: Search Console의 기간·수치와 변경일을 함께 표시
- ByteString 오류: 실제 오류 로그와 수정 커밋을 연결
- 랭킹 마지막 페이지 탐색: 지수·이진 탐색의 호출 횟수를 실제 경로별로 측정
- 추가옵션 중복 추첨: 큐브 잠재옵션과 별도 기능임을 명확히 구분
- 하루몽 초기 번들 감소: 해당 빌드와 압축 여부, 최초 요청 목록을 함께 명시

현재 문서의 적용 범위도 유지하세요. 초안 복구는 sessionStorage 세션 범위이고 마지막 500ms 입력까지 보장하지 않습니다. 컬리 장바구니 스토어 통합은 상품 담기 경로를 대상으로 하며 장바구니 페이지에는 직접 저장 코드를 남긴 상태입니다.
